# 七组打包续训预算修复候选

状态：`CANDIDATE_ONLY_NOT_DEPLOYED`。本文件不构成正式训练或部署 GO。

## 修复范围

正式七组入口原有训练阶段传递冻结截止时间，但打包中的一步续训验证遗漏了该传递；BB00 验证还会清空截止时间。

- `seven_suite.package_completed` 读取原 `TRAINING_BUDGET.json`，核对秒数与请求、起止时间差，不新建或续期预算。
- 六组共享组件的续训子进程接收原有 CLI 的 `--deadline-utc`；BB00 请求及 worker 保留相同时间。
- 在准入检查时格式错误、无时区或过期的时间阻止新的续训子进程；任何组件门禁失败（含加载、身份和续训检查）后不继续尝试剩余组件。
- 收据记录有效截止时间及预算文件 SHA；七组打包拒绝旧的未绑定证明、不同预算或不完整组件证明。
- 已经完成且精确绑定的证明可在截止后复用，不为了复制或核验文件而重新训练。

截止时间沿用训练器的“每次更新开始前检查”语义；不是强制杀进程，也不保证已开始的一步在截止时刻前结束。独立 API 的 `None` 仅保留兼容性，不代表新增训练授权。
